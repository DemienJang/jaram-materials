# Master Guide

## 운영 철학

이 프로젝트는 장재식 네이버 블로그 콘텐츠를 로컬 폴더 안에서 통합 운영하기 위한 작업 공간이다. 기능별 프로젝트를 오가는 방식이 아니라, 하나의 콘텐츠가 시작되면 그 콘텐츠 폴더 안에서 소재 정리부터 게시 확장까지 이어간다.

## 핵심 원칙

- 프로젝트는 기능별이 아니라 콘텐츠별로 운영한다.
- 하나의 콘텐츠는 하나의 폴더 안에서 관리한다.
- 블로그 글이 원천 콘텐츠가 된다.
- 스레드, 카드뉴스, 교육자료, 타이틀 이미지는 블로그 글에서 파생된다.
- 모든 작업은 장재식 블로그 문체와 콘텐츠 운영 가이드를 기준으로 한다.
- 임의의 개인 경험은 만들지 않는다.
- 결과물은 로컬 파일로 저장한다.
- 모든 가이드 수정 이력은 `guides/00_GUIDE_CHANGELOG.md`에 누적 기록한다.
- 이전 콘텐츠는 원본 폴더를 그대로 합치지 않고, 필요한 파일만 선별해 현재 구조로 이관한다.

## 프로젝트 구조

- `guides/`: 운영 규칙과 세부 가이드
- `contents/`: 콘텐츠별 작업 폴더
- `templates/`: 재사용 가능한 템플릿
- `outputs/`: 최종 산출물
- `archive/`: 완료 또는 비활성 콘텐츠
- `incoming/`: 이전 콘텐츠나 외부 자료를 선별 이관하기 전 잠시 확인하는 임시 보관 구역

## 이전 콘텐츠 이관 원칙

통합 프로젝트 생성 전에 만들어진 콘텐츠는 원본 폴더를 그대로 합치지 않는다. 먼저 `incoming/` 또는 사용자가 제공한 외부 로컬 폴더에서 원본을 확인한 뒤, 향후 참고와 이력 관리에 필요한 파일만 `contents/` 아래 콘텐츠별 폴더로 복사한다.

각 이전 콘텐츠는 하나의 콘텐츠 폴더로 정리하고, `00_brief.md`에 원본 위치, 원본 파일명, 이관 판단, 누락 또는 검토 필요 항목을 기록한다. 판단 기준과 작업 순서는 `guides/08_LEGACY_IMPORT_GUIDE.md`를 따른다.

## 기본 작업 순서

1. `AGENTS.md`와 이 파일을 먼저 읽는다.
2. 작업 유형에 맞는 세부 가이드를 읽는다. 이전 콘텐츠를 가져오는 작업은 `guides/08_LEGACY_IMPORT_GUIDE.md`를 따른다.
3. 콘텐츠별 폴더가 없으면 `contents/YYYY-MM-topic/` 형식으로 만든다.
4. `00_brief.md`를 먼저 작성하거나 갱신한다.
5. 블로그 글이 필요하면 `01_blog.md`를 작성한다.
6. 파생 콘텐츠를 같은 폴더 안에 만든다.
7. 최종 결과물은 해당 콘텐츠의 `output/` 또는 루트 `outputs/`에 저장한다.
8. 이전 콘텐츠를 이관한 경우 원본 출처와 선별 기준을 `00_brief.md`에 남긴다.
9. 가이드를 수정한 경우 `guides/00_GUIDE_CHANGELOG.md`에 수정 일시, 의도, 내용을 기록한다.
10. 작업 완료 상태와 다음 작업을 정리한다.

## 완료 기준

각 작업은 파일 저장까지 완료되어야 한다. 초안, 검토 필요, 최종본 여부를 파일 안에 명시하고, 다음 단계가 남아 있으면 마지막에 정리한다.
