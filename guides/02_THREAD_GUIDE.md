# Thread Guide

## 목적

스레드는 블로그 글을 짧게 잘라낸 요약문이 아니라, 각 편이 하나의 짧은 글처럼 읽히는 파생 콘텐츠다. 원문의 핵심 장면과 질문을 살리되 SNS에서 읽기 쉽게 다시 쓴다.

블로그 글의 전체 내용을 모두 옮기려 하지 않는다. 독자가 짧은 글 안에서도 장면, 질문, 여운을 느끼도록 구성한다.

## 작성 기준

- 각 편은 공백 포함 400~450자 이내로 작성한다. 450자를 넘기지 않되, 너무 짧은 요약문이 되지 않도록 400자 안팎의 밀도를 기본으로 한다.
- 보통 3편 구성을 기본으로 하되, 원문의 밀도에 따라 조정할 수 있다.
- 너무 짧은 요약이나 문장 조각으로 만들지 않는다.
- 원문을 그대로 줄이지 않고 스레드에 맞게 다시 쓴다.
- 원문의 중심 질문을 유지한다.
- 한 편에는 하나의 장면, 질문, 의미를 중심으로 둔다.
- 독자가 다음 편을 읽고 싶도록 흐름을 만든다.

## 기본 구성

3편으로 나눌 경우 다음 흐름을 우선 검토한다.

```text
1편: 글의 출발점이 되는 장면 또는 문제의식
2편: 그 장면에서 발견한 질문과 생각의 이동
3편: 삶으로 돌아오는 의미, 남은 질문, 짧은 마무리
```

각 편은 독립적으로 읽혀야 하지만, 전체를 이어 읽으면 블로그 글의 중심 사유가 살아나야 한다.

## 변환 순서

1. `01_blog.md`에서 핵심 장면과 질문을 찾는다.
2. 전체 스레드의 흐름을 정한다.
3. 각 조각마다 하나의 장면이나 질문이 살아 있는지 확인한다.
4. 각 편을 독립된 짧은 글로 작성한다.
5. 공백 포함 글자 수를 코드로 정확히 확인한다.
6. 반복되는 설명을 줄이고 여운이 남는 문장으로 마무리한다.

## 피해야 할 방식

- 블로그 문장을 기계적으로 잘라 붙이는 방식
- 핵심 질문 없이 정보만 요약하는 방식
- 각 편이 지나치게 짧아 문맥이 사라지는 방식
- 마지막 편이 단순 홍보나 교훈으로 끝나는 방식
- 원문의 장면은 사라지고 결론만 남는 방식

## 저장 위치

스레드 원고는 콘텐츠 폴더의 `02_threads.md`에 저장한다. 최종 게시용 정리본은 필요하면 `outputs/threads/`에도 저장한다.
